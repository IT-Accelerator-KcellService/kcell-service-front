# Реализация функционала импорта повторяющихся задач через Excel

## Обзор реализации

Данный функционал позволяет пользователям с ролями `admin-worker` и `department-head` создавать множественные повторяющиеся задачи через загрузку Excel файлов.

## Архитектура

### Backend (Node.js + Express + Sequelize)

#### 1. Роуты (`src/main/routes/recurringTaskRoutes.js`)
```javascript
// Добавлен новый эндпоинт
router.post('/import-excel', upload.single('excelFile'), RecurringTaskController.importRecurringTasksFromExcel);
```

#### 2. Middleware для загрузки файлов
- Используется `multer` для обработки multipart/form-data
- Поддерживаются форматы `.xlsx` и `.xls`
- Ограничение размера файла: 10MB
- Временные файлы сохраняются в папку `tmp/`

#### 3. Контроллер (`src/main/controllers/recurringTaskController.js`)
```javascript
static importRecurringTasksFromExcel = asyncHandler(async (req, res) => {
    // Проверка прав доступа
    // Валидация файла
    // Вызов сервиса для обработки
});
```

#### 4. Сервис (`src/main/services/recurringTaskService.js`)
- Парсинг Excel файла с помощью `exceljs`
- Валидация данных
- Создание повторяющихся задач
- Обработка ошибок

### Frontend (React + TypeScript + Next.js)

#### 1. Компонент импорта (`components/ImportExcelModal.tsx`)
- Drag & Drop интерфейс
- Валидация файлов на клиенте
- Отображение результатов импорта
- Скачивание шаблона Excel

#### 2. Интеграция с формой создания заявок
- Кнопка импорта добавлена в `CreateRequestModal.tsx`
- Доступна только для соответствующих ролей
- Адаптивный дизайн для мобильных устройств

#### 3. API функции (`lib/api.ts`)
```typescript
export const importRecurringTasksFromExcel = (formData: FormData) =>
    api.post('/recurring-tasks/import-excel', formData, {
        headers: {
            'Content-Type': 'multipart/form-data',
        },
    });
```

## Структура данных Excel

### Обязательные столбцы:
1. **Название** - название повторяющейся задачи
2. **Описание** - подробное описание (опционально)
3. **Локация** - место выполнения задачи
4. **Категория** - категория услуги (должна существовать в системе)
5. **Тип_повторения** - daily/weekly/monthly/yearly
6. **Интервал** - число от 1 до 365
7. **Дата_начала** - формат YYYY-MM-DD

### Пример данных:
```csv
Название,Описание,Локация,Категория,Тип_повторения,Интервал,Дата_начала
Ежедневная уборка,Уборка офисных помещений,3 этаж,Уборка,daily,1,2024-01-15
Еженедельная проверка,Проверка оборудования,Серверная,Техническое обслуживание,weekly,1,2024-01-15
```

## Валидация данных

### Backend валидация:
- Проверка обязательных полей
- Валидация длины строк (название ≥ 3 символа, локация ≥ 3 символа)
- Проверка существования категории в системе
- Валидация типа повторения (daily/weekly/monthly/yearly)
- Проверка интервала (1-365)
- Валидация даты (не в прошлом, правильный формат)

### Frontend валидация:
- Проверка расширения файла (.xlsx, .xls)
- Ограничение размера файла (10MB)
- Предварительная валидация перед отправкой

## Обработка ошибок

### Типы ошибок:
1. **Ошибки валидации** - неправильный формат данных
2. **Ошибки бизнес-логики** - несуществующая категория
3. **Системные ошибки** - проблемы с файловой системой, БД

### Отображение ошибок:
- Детальный отчет с указанием строки и типа ошибки
- Статистика успешных/неуспешных операций
- Возможность исправить ошибки и повторить импорт

## Безопасность

- Только роли `admin-worker` и `department-head`
